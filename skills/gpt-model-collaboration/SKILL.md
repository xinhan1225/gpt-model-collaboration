# GPT 多模型协作

先判断任务复杂度；简单任务直接完成，适合拆分且有明确收益时再协作。用户显式调用本技能，或明确采用默认协作规则时应用；安装本身不构成持续授权。启动子代理前确认用户已授权当前任务的协作及所选模型、强度；若授权不清楚，继续可独立完成的工作，按实际需要确认。用户当次要求、现行工具限制与更高优先级指令优先。

| 工作 | 默认安排 |
| --- | --- |
| 简单问答、润色、小改动、依赖紧密的短任务 | 主模型独立完成 |
| 多步骤执行、代码或文档产出 | 需要委派时用 `gpt-6.1-sol`，`medium`；复杂时用 `high` |
| 明确的检索、提取、分类、核对与批量辅助工作 | `gpt-6-luna`，`high`；固定规则优先现有工具或脚本 |
| 含糊需求、证据冲突、复杂故障、关键判断与审查 | `gpt-6-astra`，`low` 起步；难题用 `high` |

本技能路由子代理，不能更换当前聊天主模型。主模型负责目标、分工、整合与最终验证；主模型已能高效完成的工作直接执行。

启动协作前读 [协作规则](references/collaboration.md)，核对当前工具支持的模型、参数和并发限制。明确指定模型及思考强度；给子代理最小必要背景，默认不允许递归委派。通常使用一至两个子代理。

模型不可用时说明实际情况：主模型能完成就继续；确实需要替代时，只在安装用户已授权的模型中选择并告知。用户当次限定模型或服务时遵守该限定，不静默切换服务。没有可用的协作工具时由主模型继续，并如实说明未执行协作。

完成必要检查后交付，不用“多模型意见一致”代替证据。简单任务不必展示路由过程；使用协作时简述分工，交付时报告结果、验证和实质限制。所有子代理继承安装用户自己的工具、服务与媒体偏好；模型分工不改变服务路由，也不扩大外部动作授权。
