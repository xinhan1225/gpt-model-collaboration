# 协作规则

## 授权与适用范围

应用本技能不等于自动获得全部模型的调用授权。以安装用户在当前任务或其明确采用的持续规则中的授权为准；用户可以当次指定单模型、模型种类、用量或速度偏好。若未获委派授权，先完成主模型能独立处理的工作，确有必要时再确认协作范围。

授权范围是完成用户当前任务。它不改变发布、发送消息、付费、删除等动作的原有授权边界；不授权新建用户侧聊天、改变当前聊天主模型或修改全局模型配置。保持相关领域技能的适用性。

本技能是根代理的路由入口。已被委派的子代理完成分配任务即可，除非根代理明确要求且用户授权、工具限制允许，否则不再次委派。根代理应传递用户约束、工具与媒体偏好及当前适用指令。

## 按收益决定规模

| 情况 | 安排 |
| --- | --- |
| 单一明确目标、短答复、小幅修改 | 主模型独立处理 |
| 普通项目有独立子任务 | 主模型加一个 Sol 或 Luna |
| 复杂项目同时需要核心产出和资料整理 | 主模型加 Sol、Luna |
| 核心难题或关键成果需要独立审查 | 主模型加 Sol、Astra；仅在收益明确且额度允许时增加 Luna |

以实际工具公布的总并发额度为上限，计入根代理与所有后代，不假设固定额度。通常仅启动一至两个子代理。

文件提取等固定规则工作优先用脚本、已有工具或批量操作，不为每个文件创建代理。依赖同一个结果的任务按顺序执行。

## 选择模型并启动

1. 查看当前子代理工具的模型允许列表和参数。可用性以实际成功调用为准，目录中出现不等于已验证账户访问。
2. 使用 SKILL.md 的角色映射，在用户授权范围内明确传入模型和思考强度。根代理负责统筹，无需切换主模型。
3. 遵守实际工具对上下文继承和参数覆盖的约束。例如，若 `collaboration.spawn_agent` 仅在 `fork_turns: "none"` 时允许指定 `model` 和 `reasoning_effort`，则使用该参数并给出简短自包含任务书；工具定义变化时以当前声明为准。
4. 每个子代理明确自己的范围、可修改文件及不可再次委派的要求。研究或审查任务通常只读。
5. 本地有独立工作就继续执行；无独立工作时等待结果，并按环境要求报告进展。使用现有子代理的跟进工具进行定点修正。

任务书包括：目标与交付物；必要背景或来源；用户约束；可读写范围；验收条件；要求返回关键结论、证据、改动与未解决问题；未经明确指派不再委派。

共享工作区写入时，按文件或模块划分所有权。同一文件安排一个写入者，其他代理返回建议；跨文件接口由根代理统一约定。

## 独立检查与分歧

审查者收到原始需求、验收条件、必要来源和实际成果，避免只收到实施者的自评。要求具体问题、复现方式或可定位证据。

根代理按原始资料、运行结果和验收条件裁决分歧。模型投票不构成验证；主观创意取舍可以保留选择理由。独立审查不替代运行、测试、计算、引用核查或视觉检查。

默认一轮执行、一轮审查；发现具体问题后定点修正。重复失败或冲突无法解释时改变方法或在授权范围内升级模型，避免原样重试。根据可观察的耗时、返工和验收结果调整分工；只有工具提供用量数据时才报告数值，不预设协作更快或更省。

## 工具失败与用户偏好

- 辅助模型不可用：说明实际情况，主模型能处理就继续；需要辅助时只在用户已授权的其他模型中选择并告知。授权不足而确实需要替代时，请用户选择。
- 用户当次要求“只用某模型”或指定服务：不自动替换；继续不依赖该模型的工作，必要时请用户选择。
- 多代理工具不存在或受限制：明确说明，主模型在能力范围内继续，不声称已经执行多模型协作。
- 模型与强度是路由起点，不是能力保证。仅在任务确需重新比较模型时核对最新官方资料，无需每个普通任务重复联网。
- 所有代理遵守安装用户自己的工具、服务和媒体偏好；用户明确选择优先于其他技能的通用默认路由。默认服务不可用时说明情况，不静默切换。

## 媒体任务示例

用户要求制作一组游戏素材：根代理统一风格、尺寸、数量与验收要求；有必要且获授权时，Sol 整理素材清单和提示词，Luna 核对数量、尺寸与命名，复杂风格冲突可交 Astra 分析。实际生成仍使用该用户选择或授权的媒体工具。协作本身不授权调用其他媒体服务。
